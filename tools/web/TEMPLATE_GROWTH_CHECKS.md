# Template release checks and activation

The 15 curated pages have static HTML, explanatory text, direct homepage links,
canonical URLs and sitemap entries. Community cards are hidden below three
approved entries or if loading fails. They remain script-rendered: this does not
promise Google indexing. Consider generating static community pages when that
catalogue grows; do not publish unreviewed submissions for SEO.

## Search Console (site owner)

After deploying the landing folder to ripot.app:
1. Open the verified ripot.app property in Google Search Console.
2. In Sitemaps, submit https://ripot.app/sitemap.xml.
3. Inspect each new template URL from that sitemap; use Test live URL, then
   Request indexing if eligible. Confirm that Google sees the intended page.
4. Review Page indexing and Search performance after crawling. Submission does
   not guarantee indexing, rankings or a date. Search Console account access is
   required; no submission was made from this build environment.

## Campaign links and funnel

Share a public template page using, for example:
https://ripot.app/templates/colonoscopy-report-template/?utm_source=whatsapp&utm_medium=social&utm_campaign=template_launch

Keep Google search links canonical and untagged. A Google referrer is categorised
as google / organic when available; otherwise direct is used. Attribution can be
lost when browsers suppress referrers or users cross devices. Do not put patient
names, report IDs or other personal details in URLs or UTM parameters.

The hooks dispatch `ripot-funnel-ready` browser events with exactly:
`event`, `template`, `source`, `medium`, `campaign`.
Stages: template_view → editor_open → report_created → pdf_export_started.
The report event means the first successful local save of a new public-template
report in this session, including autosave. The PDF event means the browser
received a download request, not that the user saved or printed the file.
No tracking ID, cross-device identity or network collector is configured.
These hooks alone do NOT produce an analytics dashboard or conversion counts.

Before connecting a collector: select the destination/property, implement the
applicable consent controls, review its IP/device/identifier collection, disable
automatic URL/title/form/session-replay capture, and test payloads with fictional
reports. Update the public privacy policy for actual collection and retention.
If collection reaches an Android release, review Play Console Data safety for the
actual SDK and data types (including app interactions and identifiers), purposes,
sharing and deletion. Web-only hooks do not by themselves add an Android SDK.
Do not claim a Data safety submission was made: Play Console access is required.

## Contribution activation and moderation

Use the deployment, reviewer and SMTP scripts included in the release; follow
functions/TEMPLATE_LIBRARY.md. Service deployment is separate from notification
setup. Test the whole signed-in workflow with a patient-free dummy structure and
an independent reviewer. Confirm an actual reviewer email arrives. Every reviewer
must check labels, options, titles, metadata and contributor credit for patient
information, permission and suitability before publishing. Structural stripping
cannot reliably identify patient information hidden in free text.

## Print acceptance

CI exports long-report fixtures with images and signature, both free and Premium,
and checks rendered PDF geometry and branding. These are digital print-layout
checks. Before release on a particular printer, print the free long report at
Actual size on A4, then check the final signature, images and footer. Repeat with
Fit to printable area if the printer requires margins. Check Premium has no
Generated by Ripot footer. No physical printer was available in this environment.
